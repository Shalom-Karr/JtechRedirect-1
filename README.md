# Jtech Forums — landing page

A one-page site for **jtechforums.org**: the word set in block type, a tagline
that scrambles over to the next one, one link out, and a palette that changes
when you click the wordmark.

One Cloudflare Pages project serves it from six hostnames — mitmachim.com,
apps4flip.org, jtechforums.com, jtech.tripleu.org, jtech.tripleumdm.com and
jtech.jtechforums.org — each canonicalising to jtechforums.org.

Recreated from [oligarchy.fyi](https://oligarchy.fyi/), which is itself a riff on
[omarchy.org](https://omarchy.org/). Same type, same geometry, same palettes,
same interactions — the word and the copy are what changed.

```
npm install
npm run check     # compile, test, build
npm run serve     # build, then serve dist/ on :8080 (PORT overrides)
npm run deploy    # build, then push dist/ to Cloudflare Pages
```

`deploy` needs Cloudflare credentials in the environment. Use a **scoped API
token** (Account → Cloudflare Pages → Edit), never the account-wide Global key:

```
export CLOUDFLARE_API_TOKEN=...
export CLOUDFLARE_ACCOUNT_ID=2d433e3215fc8be53cc63fc504a5b993
```

The output is `dist/`: a self-contained `index.html`, two font files, a
generated `og.png`, `robots.txt`, `sitemap.xml` and `_headers`. The page makes no
external requests of its own — Cloudflare injects the Web Analytics beacon at
the edge, so it is not in the source.

## Where things are

| Path | |
| --- | --- |
| `src/config.ts` | the wordmark, the domain, the page copy |
| `src/taglines.ts` | the 128 rotating lines, shuffled |
| `src/themes.ts` | the 22 palettes, taken verbatim from the source page |
| `src/figlet/` | the block-type font, and rendering a word in it |
| `src/logo/encode.ts` | block art → one SVG path |
| `src/site/` | the stylesheet, template, favicon, SEO metadata, OG image |
| `src/client/client.ts` | the whole browser runtime |
| `src/build.ts` | assembles `dist/` |
| `test/encode.test.ts` | pins the wordmark against the live original |

Changing the word is a one-line edit in `src/config.ts`. Everything that depends
on it — the SVG, the viewBox, the width cap, the favicon, the `aria-label` —
follows from that.

## The wordmark

The type is the FIGfont `delta_corps_priest_1` (Font Author: CoSMiC cHiLD), the
face the source page sets its wordmark in. `src/figlet/glyphs.ts` carries its
A–Z glyph art, regenerated by `python3 tools/gen-glyphs.py` (needs `pyfiglet`).

The font defines **no digits and no punctuation** — those code points are blank
in the `.flf`. `renderWord` therefore rejects them rather than dropping them
silently, which is why the wordmark is `Jtech Forums` and not `jtechforums.org`.
The font is also caseless: lowercase maps onto the same art.

That art ships as vector rectangles rather than as a `<pre>`, because at phone
sizes a browser's per-glyph rounding knocks the rows out of column and the word
turns to mush. The rectangles are not an approximation of that text — they use
the same numbers the browser would have, in thousandths of an em:

| | | from |
| --- | --- | --- |
| column pitch | `557.5` | glyph advance `600` + `letter-spacing: -0.0425em` |
| row pitch | `1093.75` | `line-height: 1.09375` |
| cell | `600 × 1320` | `█`'s box in JetBrains Mono: x 0–600, y −300–1020 |
| row 0 top | `−113.125` | CSS half-leading, `−(1320 − 1093.75) / 2` |

The CSS numbers are from omarchy-site's `assets/css/pre.css`; the glyph boxes are
read straight out of the font binary. `test/encode.test.ts` re-encodes
oligarchy.fyi's *own* wordmark from the fixture in `test/fixtures/` and asserts
the result equals what that page ships — both the `d` string and the `viewBox`,
byte for byte. The viewBox is the half worth having: sized from the art's nominal
width instead of its rightmost ink it comes out one blank column too wide, and
the path still matches.

## Fonts

`public/fonts/` holds JetBrains Mono Light and Bold, self-hosted so a swapped
fallback cannot reflow the page. They are byte-identical (sha256) to the files
omarchy-site ships. Licensed under the SIL Open Font License 1.1 — `OFL.txt`
travels with them into `dist/`.

## Where this deliberately departs from the original

**The favicon.** The source page hotlinks omarchy.org's PNG. This one derives its
own instead — the wordmark's first letter, in the same block type, as an inline
SVG data URI (`src/site/favicon.ts`). That keeps the page self-contained and
leaves nothing pointing at someone else's asset. It reads clearly from 32px up;
at 16px the `J` is legible but thin, and `1.25` in that file is the padding lever.

**The two scripts in `tools/`.** The site and its build are pure TypeScript with
no runtime dependencies — neither script is in the build path and `npm run check`
never invokes them. `gen-glyphs.py` regenerates `src/figlet/glyphs.ts` and
`gen-taglines.py` reshuffles `src/taglines.ts`; both outputs are committed, so
both scripts can be deleted outright if a Python file in the tree is unwelcome.

## The tagline

128 lines: house jokes about the regulars mixed in with forum one-liners. They
are shuffled at authoring time by `tools/gen-taglines.py`, which rejects seeds
that let two house jokes land within three positions of each other — a plain
shuffle clumps them often enough to be worth retrying. Editing
`src/taglines.ts` by hand is fine; the generator only exists to reshuffle.

Each line holds for 7s, then scrambles over to the next using
[baffle](https://github.com/camwiegert/baffle) (0.3.6, MIT): the text obfuscates
for 320ms, then reveals over 900ms, characters resolving in random order. The
character pool is set to the block shapes the wordmark is built from, so the
effect reads as the same typeface. Baffle excludes the space character by
default, which is what keeps the word gaps intact and stops the line becoming a
bar of noise.

The client `import`s baffle and esbuild bundles the result into a single IIFE
that the build inlines — so the page still fetches nothing, and the build's
"no module syntax survived" guard now checks a real bundle rather than a file
that never had imports to begin with.

Where a visit starts is seeded from the clock, and so is the *stride* it walks
by. The stride is kept coprime with the list length, so one pass visits all 128
lines before any repeats — and two reloads take genuinely different routes
through the list rather than the same running order from a different offset.

Screen readers are given only settled lines: the scrambling text is
`aria-hidden`, and a visually-hidden live region is updated once the roll lands.
`prefers-reduced-motion` skips the roll entirely and swaps the text outright.

`test/roll.test.ts` runs the shipped bundle — client plus baffle — in a
hand-built DOM with the clock and timer queue under test control. It checks the
integration, not baffle's internals: that a changeover lands on the right line,
that gaps survive, that the announcement waits, that reduced motion skips it,
and that the walk covers every line.

## Hosting

One Cloudflare Pages project, `jtechredirect`, serves every hostname:

| Hostname | |
| --- | --- |
| `mitmachim.com` / `www.mitmachim.com` | apex + www |
| `apps4flip.org` / `www.apps4flip.org` | apex + www |
| `jtechforums.com` / `www.jtechforums.com` | apex + www |
| `jtech.tripleu.org` | no www — see below |
| `jtech.tripleumdm.com` | no www — see below |
| `jtech.jtechforums.org` | no www — see below |

The three `jtech.*` hostnames have no `www.` variant on purpose. `www.jtech.…`
is a *second-level* subdomain, and Cloudflare's edge certificate does not cover
that depth — attaching one was tried and its TLS handshake failed outright, so
it was removed rather than left as a hostname that looks configured and does not
resolve. Covering it would need Advanced Certificate Manager.

Each is a proxied `CNAME` to `jtechredirect.pages.dev`. The three apexes
previously carried address records that were removed to attach them; **their MX,
SPF, DKIM and site-verification TXT records were left untouched**, so mail and
domain verification are unaffected.

`jtechforums.org` itself is deliberately **not** in this list — its apex stays on
the existing `jtechforums` Pages project. Only the `jtech.` subdomain of it is
served from here.

### The redirect rules these domains used to have

`mitmachim.com`, `apps4flip.org` and `jtechforums.com` each had a Cloudflare
dynamic redirect rule — expression `true`, 301 to `https://jtechforums.org` with
the path preserved. That rule fires at the edge *before* Pages, so it had to be
turned off for this page to be visible on those domains.

The rules were **disabled, not deleted** (`enabled: false`, rule name "Redirect
to jtechforums.org"), so the previous behaviour is one toggle away in
Rules → Redirect Rules per zone.

Worth knowing that this is a real SEO trade: a 301 consolidates ranking signal
strictly better than a canonical does. Serving a landing page on these domains
is what was asked for, and the canonical is the next-best consolidation — but if
the goal is purely to pass signal to the main site, re-enabling those three
rules is the stronger answer.

Cloudflare Web Analytics is enabled per-zone with auto-install, so the beacon is
injected at the edge and does not appear in this repo.

## Search and social

Six hostnames serving identical content is duplicate content by definition. The
correct move for redirect domains is to declare it rather than fight it: every
copy carries `<link rel="canonical">` pointing at jtechforums.org, so the signal
the other five attract consolidates there. That is a deliberate trade — **the
other five will not rank on their own, by design.** If they should instead pass
signal without serving anything, 301 redirect rules are the stricter answer.

Also shipped: JSON-LD (`Organization` / `WebSite` / `WebPage`), Open Graph and
Twitter card tags, `robots.txt`, `sitemap.xml`, and security/caching headers via
`_headers`.

`og:image` points at the project's own `pages.dev` origin rather than at the
canonical host — jtechforums.org is a different Pages project and answers
`/og.png` with its own HTML, which would break every social card. See
`ASSET_ORIGIN` in `src/config.ts`.

`og.png` is generated at build time by `src/site/og-image.ts` — the same block
art, rasterised to a 1200×630 PNG written byte by byte with `node:zlib` for the
deflate, so the build stays dependency-free.



## One thing to know before this goes live

**The wordmark is 140 columns to the original's 100.** At the shared `80vw` rule
that makes the glyphs proportionally thinner on a phone, and on a wide screen
this page is bound by `80vw` where the original is bound by its rem cap. That is
the faithful consequence of a longer word under the same rules, not a bug — but
if it reads as too thin on mobile, the lever is the `80vw` in
`src/site/styles.ts`, and a shorter wordmark would sidestep it entirely.
